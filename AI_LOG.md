# Запросы, которые помогли решить задачу

## 1. Макет страницы Runs

**Запрос:**
> По прикреплённому ТЗ и стилям сайта runforge.space предложи структуру проекта по atomic design и нарисуй макет страницы Runs. Нужны список запусков, поиск, фильтр по статусу и панель деталей с логами и результатом. Левый сайдбар не делай. Стиль: молочный фон, тёмно-синие элементы, единые отступы. Статус должен отличаться не только цветом, а ещё текстом и значком.

**Контекст, который я передал:** PDF с ТЗ (модель данных, состояния, критерии оценки), ссылка на runforge.space, позже сам макет в виде HTML-файла.

**Результат:** дерево папок `atoms / molecules / organisms` и макет, который стал источником всех размеров, цветов и шрифтов для вёрстки.

## 2. Компонент Text

**Запрос:**
> Возьми стили текста из прикреплённого макета. Создай React-компонент `Text.tsx` и `Text.css` на TypeScript с вариантами: display, title, body, caption, label, badge, button, code. Все размеры сделай адаптивными через `clamp()`, `rem` и `vw` (от 360px до 1280px, значения из макета — максимум). Код пришли текстом, не файлом.

**Контекст, который я передал:** HTML-файл макета со шрифтами, размерами, межстрочными интервалами и letter-spacing.

**Результат:** единый компонент `Text` с вариантами и тонами (`default`, `muted`, `danger`, `inverse`), который используется во всех остальных компонентах вместо отдельных стилей текста.

## 3. Dev-панель для управления состоянием и данными

**Запрос:**
> Создай компонент `DevPanel` для разработки: он должен менять состояние и данные без правки кода. Нужны выбор набора мок-данных (по умолчанию, пусто, много запусков, длинные тексты), задержка запроса, включение ошибки, перезагрузка данных и сброс фильтров. Построй по схеме проекта: контекст, провайдер, хук

**Контекст, который я передал:** уже написанные `useRuns`, `runsApi`, `mockRuns`, провайдеры `RunsFiltersProvider` и `RunDetailProvider`, структура папок проекта.

**Результат:** `DevSettingsProvider`, хук `useDevSettings`, обновлённые `useRuns` и `runsApi`, наборы данных для проверки граничных случаев и сама панель. С её помощью проверил загрузку, ошибку, пустой результат и переносы длинного текста.
