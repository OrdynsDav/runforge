# Запуск проекта

```bash
npm i
npm run build
npm run preview
```

Перейти на страницу http://localhost:4173

# Тесты

Автотестов нет, так как с тестами я раньше не работал. Вместо них проверил вручную:

- адаптивность (ширина окна от 360 px);
- открытие и закрытие сайдбара справа;
- поиск и фильтрацию по статусу;
- совместную работу поиска и фильтра: например, статус Succeeded и запрос «web» оставляют только подходящие запуски;
- пустой результат: при запросе, которого нет в данных, появляется сообщение и кнопка «Сбросить фильтры и поиск», после нажатия список возвращается;
- загрузку: пока mock-запрос выполняется (900 мс), вместо списка виден скелетон;
- ошибку: при включённой ошибке запроса показывается сообщение и кнопка «Попробовать снова», после её нажатия данные загружаются;
- запуски без длительности или результата (Queued, Running): в списке стоит «—», в сайдбаре «No result yet.», интерфейс не ломается;
- длинные названия и ветки: текст обрезается многоточием и не ломает вёрстку;
- управление с клавиатуры: Tab переключает фильтры и строки списка, Enter открывает детали.

# Краткое описание структуры проекта

Проект написан по принципам atomic design.

```
src/
├── api/          # mock-сервис: fetchRuns() возвращает Promise с задержкой
├── app/          # точка входа приложения
├── atoms/        # минимальные элементы: Text, StatusBadge, иконки
├── molecules/    # RunCard, RunsList, LogViewer, StateMessage, Header
├── organisms/    # SearchFilterToolbar, RunsSection, RunDetailSidebar, RunsContent, DevPanel
├── pages/        # страницы
├── context/      # провайдеры: фильтры, детали запуска, dev-настройки
├── hooks/        # useRuns, useRunsFilters, useRunDetail, useDevSettings
├── data/         # mock-данные
├── types/        # типы Run, RunStatus и другие
└── utils/        # форматирование дат и длительности, фильтрация, clsx
```
